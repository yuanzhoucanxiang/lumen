# LUMEN 素材库导入

> 本技能由 LUMEN 应用随安装包分发（LUMEN 设置 →「Agent 接入」一键安装/更新）。
> LUMEN 更新后可重新安装以获得最新版技能。

LUMEN 是用户本机的素材管理桌面应用（类 Eagle）。它在运行时提供一个仅监听本机的 HTTP 服务，agent 可以把散落在磁盘各处的图片/素材批量导入库中，并顺手打标签、归文件夹。

## 第 0 步：确认 LUMEN 正在运行

```bash
curl -s -H "x-lumen-client: lumen-clip/1" http://127.0.0.1:45678/status
```

- 返回 `{"ok":true,...}` → 服务可用，继续。
- 连接被拒（Connection refused）→ LUMEN 没在运行。告诉用户"请先启动 LUMEN"，等启动后重试。不要替用户强杀/重启 LUMEN 进程。
- `/status` 正常但 `POST /import` 返回 404 → 用户安装的 LUMEN 版本过旧（未提供本接口），提示用户更新 LUMEN。
- **顺便看 `skill` 字段**（本技能版本自检）：`{"installed":true,"upToDate":false,"dirs":["…"]}` 表示用户装在你身上的这份技能**不是最新**——
  如果响应里还带了 `skillUpdateHint`，就按它说的提醒用户：打开 LUMEN「设置 → Agent 接入」点「更新技能」。
  **用户更新后，用 `skill.dirs` 里的路径重新读取 `SKILL.md`**（通常 `dirs[0]/SKILL.md`），按新内容继续；
  提醒一次即可，不要反复催；在更新前按你当前掌握的约定继续工作。

## 导入图片（主要用法）

用本技能自带的脚本，避免手写 JSON 时路径转义出错：

```bash
node "<本技能目录>/scripts/import.cjs" --paths "C:/图1.png" "C:/输出/整套截图" --tags "AI生成,海报设计" --folder "AI生成/2026-10"
```

参数说明：

| 参数 | 说明 |
| --- | --- |
| `--paths` | 一个或多个文件/目录路径，必填，**必须是绝对路径**（相对路径会被拒绝）。目录会递归导入其中全部文件（最多 1000 个路径） |
| `--tags` | 可选，逗号分隔。给本次新导入的素材追加标签；标签不存在会自动创建 |
| `--folder` | 可选。把新导入素材归入该文件夹；支持 `A/B` 多级路径，缺失的层级会自动逐级创建（最多 5 级）。**未指定时新导入素材自动归入「Agent 导入」专属文件夹**，与用户自己的素材分开。**在自己可写的文件夹（含「Agent 导入」）下可以直接建子文件夹**，用来按 agent / 任务 / 日期分开存放——见下节；**不能是智能文件夹**（同名会返回 409，请换名） |
| `--note` | 可选。生成信息存档：把 prompt、模型名、参数等写进素材备注（仅作用于新导入的素材），之后在 LUMEN 里搜备注关键词就能找到"这张图当时怎么生成的" |
| `--check-similar` | 可选开关。导入时对每张新图做相似检测，响应的 `similar` 数组会列出库内近似素材（dHash 感知哈希命中）——AI 批量出图前用它防止近重复图淹没图库，收到 `similar` 告警时如实告知用户 |
| `--dry-run` | 可选开关。试运行：只展开路径、预估会导入/跳过多少文件并回传 `missing`，不真正导入。大批量导入前先跑一遍是稳妥做法 |
| `--board` | 可选，白板 id。新素材导入后直接放上该白板画布（自动流式排布）；可用 `GET /boards` 列出现有白板拿 id |
| `--auto-tag` | 可选开关。导入后在后台用 AI 自动打标签（需要用户已配置 AI；耗时分钟级，完成后 LUMEN 界面会提示）。**默认关闭**：这一步会把图片缩略图发送给所配置的模型，需用户在 LUMEN「设置 → Agent 接入」打开「允许 AI 自动打标签」；未授权时请求返回 403，图片不外发 |
| `--move` | 可选开关。导入后删除源文件（默认是复制，源文件保留——不确定时不要加）。**默认关闭**：需用户在 LUMEN「设置 → Agent 接入」打开「允许移动导入」；未授权时请求返回 403 且源文件保持不动。授权后源文件也是在数据库确认落库之后才删 |

脚本成功时输出类似：

```json
{"ok":true,"imported":12,"skipped":3,"failed":0,"failedFiles":[],"importedIds":["a1b2c3"],"matchedIds":["d4e5f6"],"files":[{"path":"C:/图1.png","name":"图1.png","status":"imported","id":"a1b2c3"}],"missing":[],"folderId":42}
```

## 归档分类：跟着你手上的工作建子文件夹

**默认动作**：每批素材都放进一个**和"你正在做的事"对应**的子文件夹，不要平铺进「Agent 导入」。
用户不需要额外交代"请分类"——这是你的默认习惯。

**起名方向**（给方向，不用套模板）：用这次工作的任务名或阶段，短、一眼能看懂：
- `Agent 导入/角色三视图-赛博鸦`
- `Agent 导入/2026-10-08 分镜草稿`
- `GIR项目/线稿/鸦-定稿`

一层通常够用，同一任务再分阶段最多两层。**不要为了"整齐"自建一套分类体系**——
「参考图 / 角色 / 场景」这类词在明显合适时才用，不要见缝插针地套；也别建空壳夹，只建这次真有素材要放的。

**工作流**

1. `GET /scope`（只读）：拿到可写位置（`allowed[].path` / `defaultFolder`）和**已有的子文件夹**
   （`allowed[].subfolders` / `defaultSubfolders`）。
2. **能复用就复用**：已有子夹装得下这批图，就直接用它的路径——不要造近义夹
   （有「参考图」就别再建「参考」「Reference」）。
3. 没有合适的，按这次工作新建（缺失层级会自动创建，不需要先建文件夹）。
4. 同一任务反复导入用**同一个**子夹；不要每次按时间/批次新建，除非用户要留历史版本。
5. 导入时传 `--folder "…"` / `folder: "…"`。
6. 汇报里写明归到哪：例如"12 张参考图已导入「Agent 导入/角色三视图-赛博鸦」"。

## 整理已有素材（不是导入，是把库里现有的图分好类）

用户说"帮我整理一下库里的图""这些图太乱了"时，**先摸清现状，再提方案，得到确认后分批执行**——
不要一上来就大批量改，用户没法预判你会动什么。

**1. 摸底（都是只读，可放心调）**
- `GET /folders` — 现有文件夹树（含每个夹的素材数）；`GET /tags` — 标签及使用数；`GET /stats` — 库规模 + **未归档/未打标签/已标星的数量**（先看缺口有多大）。
- `GET /assets?untagged=1` — 还没打标签的；`GET /assets?folder=<id>` — 某个夹里有什么；
  `GET /assets?folder=none` — **不属于任何文件夹**的（整理时先把这些捞出来）。
- `GET /assets` 每行带 `folderIds`（当前归属），据此判断"它现在在哪、要不要挪"。
- 不要逐条 `GET /asset` 去拼全库——先按条件筛出目标集合（数量、分布），再决定怎么处理。

**2. 提方案（必做）**
用一段话说清：按什么标准分组、每组大概多少张、放到哪些夹 / 打什么标签、会不会动到已有文件夹。
给 1–2 个方案让用户选（例如"按用途分：参考图/角色/场景" vs "按项目分：GIR/其他"），说明你的推荐。
用户确认后再动手；用户说"你看着办"就按推荐方案执行，但先说明你要改什么。

**3. 执行（分批、可回退）**
- 打标签：`POST /tag {"tag":"…","conditions":{…}}`（按条件批量）或 `{"tag":"…","ids":[…]}`。
- 归档：`POST /folder {"folder":"A/B","conditions":{…}}`。
- **移动 = 先加后减**：素材可以同时属于多个文件夹，真正的"从 A 挪到 B"要两步——
  `POST /folder {"folder":"B", …}` 再加入 B，然后 `POST /unfolder {"folder":"A", …}` 从 A 移出。
  只加不减会同时挂在两个夹里。
- 备注/星级同理（`/note`、`/star`），都支持 `conditions`。
- **每批做完汇报一次**（改了多少张、加到哪），再继续下一批；批量操作都会进操作记录。
- 不要删除素材、不要改用户原有的文件夹结构（重命名/删除文件夹没有 Agent 接口，也不需要）。

**4. 校验与善后**
- 用 `GET /assets?folder=<id>`、`?tag=<名>`、`?untagged=1` 复核数量对不对。
- 改错了：`GET /ops` 找到这批记录的 `groupKey`，`POST /undo {"groupKey":"…"}` **整批撤回**（一次导入/整理对应一个 groupKey）。
- 发现重复图：用 `POST /similar` 或导入时的 `checkSimilar` 找出来，**如实报告给用户**请你决定，不要试图自动删（Agent 没有删除权限）。

## 不确定时先问用户（默认就有这个能力，主动用）

你可以、也应该在**动手前征询用户**——尤其是"放哪个文件夹"和"要不要新建文件夹"这两件事。

**什么时候问**
- **需要新建文件夹**，而用户没说过要叫什么、放在哪 → 先问，别自己拍板。
- 有多个都说得通的候选、且选哪个会影响后续（比如两个项目夹都在可写范围里）→ 先问。
- 用户的指令很开放（"帮我整理一下""随便分分""你看着办"）→ 先问，或给一个方案让用户确认。
- 库里的既有分类明显和这批图不搭（比如把线稿放进"最终稿"）→ 先问一句确认。

**什么时候不用问**
- 用户已经指定了位置或名字 → 直接用，别再确认。
- 已有同类子夹能复用 → 直接用，并在汇报里说"放进已有的 X"。
- 只是继续往本轮已确认的子夹里追加 → 不再重复问。

**怎么问**（一次问清，别连环追问）
- 给**具体选项**，而不是空泛地问"放哪"：从 `/scope` 里挑 1–2 个最相关的已有夹 + 1 个你建议的新夹名，
  再给一句默认："建议新建「Agent 导入/角色三视图-赛博鸦」，或放进已有的「Agent 导入/角色」？"
- 用户给了答案就照做，**同一任务后面不要再问同一个问题**（记住这次的选择）。
- 用户说"你决定 / 别问了 / 先这样" → 按任务名建夹，一句话说明你的选择，之后沿用这个夹。
- 用户没有及时回复时不要卡住：先不导入（不要为了推进而乱放），或按你已经说明的默认方案执行并明确告知。

**权限边界**：用户没勾任何文件夹时，你能写的只有「Agent 导入」**及其子文件夹**；想写到别处（比如项目文件夹），
请用户去 LUMEN「设置 → Agent 接入 → 可写入文件夹」勾上——不要绕路往别处塞。

## 行为要点（决定你怎么向用户汇报）

- **查重以文件内容为准（SHA-256）**：库中已有内容完全相同的文件会被 `skipped`（改过文件名也能命中），不会重复入库；同名同大小但内容不同的文件不会被误判为重复。同一批路径可以放心重复执行。
- **落位路径直接可用**：响应里的 `folderPath` 就是这批素材实际归入的文件夹完整路径（未指定时为「Agent 导入」），
  `createdFolders` 是本次请求**新建**的文件夹路径列表。汇报位置时直接引用它们，不要自己拼。
- **回退会清理新建的空夹**：用户撤销 Agent 的操作时，本次新建、且已经变空的文件夹会一并删除（有素材/有子夹的不动）；
  所以不用担心"撤销后留下空壳夹"。
- **`files` 逐文件明细**：`path` + `status`（imported/skipped/failed）+ `id`。汇报和重试都以它为准；`failed` 的文件可以单独重试。
- **标签/文件夹作用于本次涉及的全部素材**：新导入的文件照常打标签归档；被 `skipped` 的重复文件（即库内已有的同内容文件）也会补上标签/归入文件夹。因此"同一批路径 + 同一组标签"重跑结果幂等；换一组标签重跑则会给库里已有的同内容素材补上新标签。
- **只收视觉素材**：图片 / 视频 / 音频 / 字体之外的普通文件（`md`、`py`、`txt`、`json`、`pdf`、压缩包等）**会被 LUMEN 忽略**，不会进素材库。响应里的 `unsupported` / `unsupportedFiles` 就是被忽略的个数与文件名——如实报给用户（"其中 3 个文档类文件已忽略"），不要反复重试或试图改名混进去。
- **可写范围默认只有「Agent 导入」**：往其它文件夹归档/导入需要用户先在 LUMEN「设置 → Agent 接入 → 可写入文件夹」把该文件夹（含子文件夹）勾上。越界会返回 403 与提示文案，别反复重试——如实告诉用户去哪里勾选即可。
- **危险动作需授权**：`--move`（删源文件）与 `--auto-tag`（图片外发）默认关闭，需用户在 LUMEN「设置 → Agent 接入」显式打开。被拒时接口返回 403 且整批不做（不会半个请求生效）；遇到 403 如实告诉用户去哪里打开，不要反复重试。
- **标记以 LUMEN 图库为准**：LUMEN 里的标签/星级/备注只是 LUMEN 侧的整理信息，不能反向替代其它工具的权威记录（例如素材本身的工程文件与认可记录）。
- **`missing` 非空**说明有路径不存在（多半是写错了），如实告诉用户哪些路径没导入。
- **`failedFiles` 非空**说明有文件导入失败（损坏文件等），列出文件名。
- **默认归入专属文件夹**：未指定 `--folder` 时，agent 新导入的素材自动进入「Agent 导入」文件夹，与用户自己的素材分开、互不混淆；显式指定 `--folder` 则按指定归档（此时会同时作用于库内已有同内容素材，实现幂等归档）。
- `folderId` 是文件夹 id（可能是新建的），可向用户确认归类位置。
- 默认复制导入，源文件不动。确属"收纳散落图片"场景且用户明确同意后，才用 `--move`。

## 备选：直接调 HTTP API

脚本不可用（比如没有 node）时可以直接 curl。注意 Windows 路径在 JSON 里建议用正斜杠，避免转义地狱：

```bash
curl -s -X POST http://127.0.0.1:45678/import \
  -H "x-lumen-client: lumen-clip/1" -H "Content-Type: application/json" \
  -d '{"paths":["C:/output/img.png"],"tags":["AI生成"],"folder":"AI生成"}'
```

其他端点（均需带同样的鉴权头）：

- `GET /scope` — **我的可写范围 + 已有分类**（只读）：`allowed`（允许写入的文件夹，`path` 可直接作为 `folder` 参数）、`allowed[].subfolders` 与 `defaultSubfolders`（**已有的子文件夹完整路径，优先复用**）、`defaultFolder`、`subfoldersAllowed`、`unrestricted`、`hint`。导入/归档前必看。
- `GET /status` — 服务探测 + **技能版本自检**：`version`、`library`、`skill:{installed,upToDate}`；`upToDate:false` 时另带 `skillUpdateHint`（提醒用户去设置里更新技能）。
- `GET /assets` — 查询素材（只读）。参数：`q`=关键词（搜名称和备注，含拼音，比如用 prompt 片段找图）、`ext`=逗号分隔扩展名、`tag`=标签名、`source`=来源（manual/agent/clip/watcher/screenshot）、`days`=最近 N 天、`star`=最低星级、`shape`=landscape/portrait/square、`untagged=1`=未打标签、`folder`=文件夹 id（`folder=none` 只看**未归档**）、`minW`/`maxW` 宽度、`minKB`/`maxKB` 体积、`sort`=imported/name/size/star + `order`=asc/desc（按名字默认正序，其余默认倒序）、`limit`≤500、`offset` 分页。响应含 `count/truncated/assets`（窄列：id/name/ext/宽高/大小/来源/标签/**当前归属 folderIds**）。**生成或导入前先查一下库里有没有，避免重复劳动**。
- `GET /similar?id=xxx&maxDistance=12&limit=60` — **以图搜图**（只读，确定性 dHash 检索）：给一个库内素材 id，返回库中与它相似的素材（含 `matchPct` 相似度百分比，按相似度降序）。适合'这张图还有没有近似版本/重复'类需求。
- `POST /similar` — **外部图片查重**（只读）：body `{"dataUrl":"data:image/...;base64,...","maxDistance":12,"limit":60}`，`maxDistance` 0-32、`limit` 1-200、dataUrl 上限 20MB。适合"这张新图还没入库，先看看库里有没有近似的"；也接受 `{"assetId":"..."}`（等价于 GET）。响应同 GET（含 `matchPct`）。
- `GET /asset?id=xxx` — 单素材详情：含 `comment`（生成信息存档在这里，可读回 prompt）、来源、标签、**归属文件夹 `folders`（完整路径）**。
- `POST /tag` — 打标签：body `{"tag":"标签名","conditions":{...}}` 或 `{"tag":"...","ids":["..."]}`，给全部命中素材打标签（幂等）。
- `POST /untag` — 摘标签：参数同上，从命中素材上移除该标签（可逆）。
- `POST /folder` — 归档：`{"folder":"A/B","conditions":{...}}`（文件夹不存在自动创建），把已有素材归入文件夹。
- `POST /unfolder` — **移出文件夹**：`{"folder":"A/B","ids":[…]}` 或带 `conditions`；只对**已存在的文件夹**生效（不新建），目标必须在可写范围内。返回 `removed/folderId/folderPath`；可回退（回退会放回）。
- `POST /star` — 星级：`{"star":0-5,"ids":[...]}` 或带 `conditions`。
- `POST /board` — 上板：`{"boardId":N,"ids":[...]}`，把已有素材追加到白板（自动流式排布）。
- `POST /note` — 备注：`{"note":"...","mode":"append","ids":[...]}`（mode 缺省为改写），给已有素材写/追加备注。
- `GET /ops` — **操作记录**：列出你做过的写操作（**含逐项明细 `items[]`** 与能否回退）。改动用户素材后建议主动向用户汇报；用户可在 LUMEN 助手面板查看并**逐项或整条回退**。
- `POST /undo` — 回退：`{"id":N}` 整条、`{"id":N,"itemIds":[...]}` 逐项、**`{"groupKey":"…"}` 一次撤掉同一批请求产生的全部记录**（一次带标签+归档的导入会生成多条记录，用 groupKey 最省事）。回退时本次新建、且已变空的文件夹与标签会被一并清理（有内容的不动）。
- `GET /stats` — 库汇总（只读）：素材总数、回收站数、标签/文件夹数、Agent 来源数，以及**整理缺口 `unfiled`（未归档）/ `untagged`（未打标签）/ `starred`（已标星）**——摸底时一次拿全。
- `GET /tags` — 列出现有标签（含 id/name/count）。打标签前可先看看有没有语义相近的既有标签，优先复用，避免同义标签泛滥。
- `GET /folders` — 列出现有文件夹（含 id/name/parentId/count）。同理优先归入既有文件夹。
- `GET /boards` — 列出现有白板（id/name），配合 `--board` 使用。
- `POST /clip` — 单图导入（body 传 `{"dataUrl":"data:image/png;base64,..."}`），适合图片还没落盘、只有内存字节的场景；已落盘的文件一律用 `/import`。

## 汇报格式建议

导入完成后用一两句话汇报：导入/跳过/失败的数量、打上的标签、归入的文件夹，以及（若有）缺失或失败的文件。不要把 importedIds 长列表贴给用户。
